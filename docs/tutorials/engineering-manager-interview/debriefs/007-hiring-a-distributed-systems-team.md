# Debrief 007: Hiring a Distributed-Systems Team

Map capabilities first: domain, Python application design, distributed correctness, data/storage, Kubernetes operations,
reliability, security, technical leadership, and product collaboration. Decide which can be developed internally and
which gaps need experienced hires. Five identical seniors create cost, unclear roles, and weak growth paths.

A balanced plan may combine a technical lead with operated-distributed-systems evidence, experienced backend engineers,
and existing domain engineers supported by pairing and training. Hire for learning and production judgment, not trivia.

Use a structured loop: practical Python/code reasoning, system design with explicit requirements, incident/operations,
collaboration, and role-specific leadership. Each has anchored evidence and no duplicate "general fit" vote. Calibrate
interviewers and audit funnel outcomes.

Onboarding includes architecture, domain, shadow on-call, safe first change, service ownership, and a recovery exercise.
Measure time to safe contribution, on-call readiness, design ownership, retention, and distribution of knowledge. Weak
answers list technology keywords or assume hiring replaces internal development.
