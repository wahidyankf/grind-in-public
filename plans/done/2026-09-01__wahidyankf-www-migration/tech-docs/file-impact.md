# File Impact

Every path this plan expects to touch, labelled `[E]` edit, `[N]` new, `[M]` moved, or `[D]` deleted. A path absent from
this list is a path the plan did not anticipate, which is a signal to stop and amend rather than to improvise.

Eleven source paths are deliberately **not** ported and appear nowhere below. Every one is a path a copy could plausibly
pick up, so each is named rather than left to be noticed as an omission:

- `apps/wahidyankf-www/Dockerfile` and `apps/wahidyankf-www/.dockerignore`, because this repository deploys through
  Vercel and runs E2E against `next start`.
- `apps/wahidyankf-www-e2e/scripts/run-docker-e2e.mjs` and `apps/wahidyankf-www-e2e/e2e-coverage-baseline.json`, because
  the Docker runner is dropped and the baseline file is consumed only by `rhino-cli`. A differently-shaped baseline is
  authored in its place: `apps/wahidyankf-www-e2e/e2e-skip-baseline.json` below holds the generated `test.fixme` count
  as a single integer, which is what the `specs:e2e:baseline` target compares against. The ported file holds an
  `allowedUnbound` list in a shape only `rhino-cli` reads.
- `apps/wahidyankf-www/oxlint.json`, because Biome replaces oxlint. It is read once, in Phase 1, as the reference for
  what the new root `biome.json` must cover, and then left behind. If the Phase 3 Biome fallback fires, it is copied at
  that point and this list is amended.
- `apps/wahidyankf-www/project.json` and `apps/wahidyankf-www-e2e/project.json`, because both target contracts are
  authored fresh against this repository's Nx rules rather than ported. Copying either would bring `test:specs`,
  `specs:structure-validation`, `specs:behavior:coverage`, `specs:e2e:coverage`, and their `dotnet run` commands with
  it. The two destination `project.json` files below are therefore `[N]` as authored files, not as copies. Authoring
  fresh also drops two guard clauses the source prepends to its own commands, and each is settled here rather than left
  as an omission. The source `test:unit` prepends a `grep` that fails the run when `it`, `test`, or `describe` is
  followed by `.skip`, `.only`, or `.todo`; that one is **not** carried. The 99% line floor on `test:coverage:unit`
  already fails on the coverage a disabled or narrowed test stops producing, and `apps/badakmini-cli`, this repository's
  only existing precedent for the target, carries no such clause either. The source `test:e2e` prepends a `grep` that
  fails the run on an unconditional `test.skip(...)`; that one **is** carried, by the Phase 5 item that writes the new
  `test:e2e` command, because nothing here would replace it: `specs:e2e:baseline` counts `test.fixme` entries in
  generated files, which a hand-written `test.skip()` in a step file never becomes, and this project carries no coverage
  floor for a silently skipped scenario to drop below.
- `libs/web-ui/src/utils/cn.ts`, because the application already owns the same helper.
  `apps/wahidyankf-www/src/features/app-shell/core/style.ts` exports a `cn` with the same body and the same `clsx` and
  `tailwind-merge` imports, and `style.unit.test.ts` already covers it; none of the four components inlined from
  `web-ui` imports `cn` at all. Porting it would put a second `cn` and a second test for one function into the 99%
  denominator.
- `apps/wahidyankf-www/src/features/search/shell/SearchSection.tsx`, because nothing imports it. It exports one
  constant, `SEARCH_PLACEHOLDER`, and a search of the whole source repository at the recorded commit finds no importer
  of either the file or the constant outside archived plan documents. Phase 3 reruns that search and removes it; if the
  search does find an importer, the file is ported, renamed, and given a unit test, and this list is amended.
- `apps/wahidyankf-www/.env.local`, because it is a real tier env file holding real values. It is untracked and matched
  by `apps/wahidyankf-www/.gitignore`'s `.env*.local` rule in the source repository, and
  [plan document safety](../../../../repo-governance/conventions/plans-organization-policy/plan-document-safety.md)
  forbids a credential or a runtime value reaching a committed plan or the tree it describes. Every copy list in
  `delivery.md` names its files individually rather than globbing the directory, which is what keeps this file out;
  `.env.example` is the one that comes.
- `apps/wahidyankf-www/tsconfig.tsbuildinfo`, because it is a 168 KB incremental-build cache, untracked and matched by
  the root `.gitignore`'s `*.tsbuildinfo` rule in the source repository. It is regenerated by the first `typecheck` run
  here.

Three verification artifacts are written to the gitignored `local-tmp/` directory and carry no label, because nothing
tracks them and nothing outside the run that writes them reads them: `local-tmp/step-cardinality.txt` in Phase 2, and
`local-tmp/cv-digests-before.txt` with `local-tmp/cv-recovery/` in Phase 4.

Phase 1 adds six ignore rules to the root `.gitignore` for generated paths that are likewise unlabelled:
`*.tsbuildinfo`, `.next/`, `coverage/`, `test-results/`, `playwright-report/`, and `.features-gen/`. `*.tsbuildinfo`
covers `apps/wahidyankf-www/tsconfig.tsbuildinfo`, which the ported `incremental` plus `noEmit` compiler options make
the first `typecheck` write and which no existing rule in this repository matches. The other five arrive already ignored
for Git — `.next/` and `coverage/` by `apps/wahidyankf-www/.gitignore`, and `test-results/`, `playwright-report/`, and
`.features-gen/` by `apps/wahidyankf-www-e2e/.gitignore`, each copied before anything generates the directory it names —
and they still need a root rule, because Git is not the only reader. `npm run format:check` is `prettier --check .` run
from the workspace root, and Prettier resolves ignore patterns from the root `.gitignore` and a root `.prettierignore`
alone; it never reads a nested `.gitignore`. An earlier revision of this document dropped the five directory rules on
the Git reasoning above, which is why they are back: that reasoning was true for `git status --short` and silent about
`format:check`. Every generated path in this repository is matched by the root `.gitignore` today, which is the only
reason `format:check` has never had to skip one; this plan is the first to add output that a nested file alone would
cover, and without the root rules the Phase 3 gate's `format:check` fails on the `.next` tree `static-routes:validation`
leaves behind. No root `.prettierignore` is introduced, because the root `.gitignore` already reaches every path in
question and a second ignore file would give this repository two places to keep in step.

Every other file this plan takes from `ose-public` is labelled `[N]`, not `[M]`. `[M]` is reserved for the paths that
genuinely move **within this repository** — the three CV documents — because `ose-public` is not touched and none of its
files disappears.

`apps/wahidyankf-www/tsconfig.json`. If either turns out to need a change, that is a discovery that stops execution and
amends this plan, not something to improvise.

Three of those options — `module`, `moduleResolution`, and `target` — put both new projects outside the language target
`code-style-policy.md` states. Both override them on top of the `tsconfig.base.json` they extend; the E2E project's
ported `tsconfig.json` has no `extends` at the source commit and Phase 5 adds one. That is a named deviation, not an
unnoticed one: [technical design](README.md#toolchain-conformance-and-its-fallback) records it beside the toolchain
fallbacks and gives it the same recording duty, a dated `learnings.md` entry and an amendment to
`testing-policy/tooling.md`.
